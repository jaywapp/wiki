# Windows Terminal 작업 공간 분석

- orchestrator: Codex
- 요청: Windows 기준으로 권장한 오케스트레이터 + N개 프로젝트 터미널 구성을 실제 설정한다.
- 확인: Windows Terminal과 Windows용 Codex/Claude CLI가 설치되어 있다. 워크스페이스는 `D:\work`, 기존 Terminal 프로필은 7개다.
- 결정: 왼쪽 오케스트레이터 35%, 오른쪽 프로젝트 65%의 독립 창을 사용한다. 프로젝트 탭은 AI 75%, 로그용 PowerShell 25%로 나눈다.
- 기본 도구: Codex. Claude는 별도 실행 진입점으로 제공하며 작업 경계에서 전환한다.
- 프로젝트 선택: 전체 저장소를 한꺼번에 실행하지 않고 Terminal 명령 팔레트에서 저장소 이름을 검색한다.
- 가정: 현재 요청은 기존 GUI의 설정이다. 신규 GUI 프로젝트나 웹 페이지 제작은 포함하지 않는다.
- 범위: `.workspace/windows-terminal` 설정 원본, 사용자 Terminal 설정에 추가 항목 병합, 실행 바로가기, wiki 문서.
- 기존 설정과 단축키를 보존하고 적용 전 로컬 백업을 만든다. 세션 간 메시지 라우팅, 자동 작업 위임, tmux/WSL 전환, 배포는 포함하지 않는다.
- 핵심 미확정 요구사항: 없음. 사용자가 직전 권장 배치를 승인했다.
- 완료 기준: 설정 JSON 검증, 기존 항목 보존 확인, 두 창 실행, 프로젝트별 탭/분할 명령 생성 확인.
