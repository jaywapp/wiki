# 위키 웹 리더 설계 초안

## 확인된 요구사항

웹 호스팅, 문서 읽기, 검색, 트리·리스트 보기, 필터, 정렬. 개인 개발 지식을 재탐색하는 읽기 중심 웹 화면이다.

## 데이터와 흐름

확정할 원본 Git 브랜치 → 빌드 시 공개 Markdown 목록과 Git 변경일 수집 → 안전한 Markdown 렌더링과 검색 인덱스 → 정적 웹 배포. 클라이언트에서 검색과 분류 필터를 교집합으로 적용한 후 정렬하고 트리 또는 목록으로 표시한다. 문서 본문에는 제목, 경로, 수정일, 목차, 코드·표를 제공한다. 문서 URL과 검색 상태는 공유 가능한 주소로 유지하는 방향을 제안한다.

검색은 한글·영문 부분 문자열과 대소문자 정규화를 지원한다. 트리는 일치한 문서의 부모 폴더를 보존하고 폴더 안 문서에 정렬을 적용한다. 정렬 동률은 경로로 결정한다. 문서 내 상대 링크와 앵커는 웹 문서 주소로 변환한다. 외부 링크는 안전한 프로토콜만 허용한다. 원시 HTML을 실행하지 않는다. 코드의 줄바꿈·가로 스크롤, 표, Mermaid 사용 여부는 조사 결과에 따라 구현한다.

## 화면 콘셉트

### 자료 카탈로그 추가 시안

사용자가 카탈로그 레이아웃을 지정했으므로 목록 중심 배치와 공통 자료·기능은 유지한다. 기존 impeccable/design-taste-frontend 방향과 검증 기준을 이어서 적용한다. 새 방향 추첨은 하지 않는다.

- A / 클리어: 밝은 백색, 절제된 코발트, 부드러운 행 선택과 넉넉한 여백. 일반 본문은 산세리프. 탐색 제어와 문서를 명확히 구분.
- B / 그래파이트: 짙은 회색, 연한 녹색, 작은 제목과 조밀한 행, 경로는 고정폭. 정보 스캔과 야간 사용에 집중.
- C / 페이퍼: 밝은 종이색, 갈색, 명조 문서 제목과 가는 구분선. 메타데이터를 보조 정보로 낮추고 본문의 읽기 리듬 강화.

모바일은 분류를 가로 스크롤로 압축하고 하단 탐색/본문 이동을 제공한다. 터치 컨트롤은 최소 44px을 기본으로 사용한다. 샘플 문서·날짜 표시는 유지한다. 각 시안의 데스크톱, 모바일 목록, 모바일 본문을 캡처하여 대화 안에서 제시한다.

- concept-01 / 탐색 서재: 밝은 중성색과 짙은 녹색. 좌측 분류, 가운데 목록, 우측 읽기 패널. 탐색 속도가 강점. 작은 화면은 세로 배치. 상태 변경만 짧게 전환.
- concept-02 / 읽는 노트: 종이색과 먹색, 출판물 성격의 명조 제목. 상단 탐색과 넓은 본문, 목록은 접을 수 있는 보조 영역. 긴 글 가독성이 강점. 본문 등장만 부드럽게 전환.
- concept-03 / 자료 카탈로그: 어두운 중성색과 청록 강조. 전체 너비의 조밀한 자료 목록, 아래 본문. 경로·날짜 비교가 강점. 즉각적인 상태 전환.

모든 콘셉트는 동일한 예시 문서와 기능을 사용한다. 운영 브랜드는 선택 전 미확정이다. impeccable의 Read 모드와 design-taste-frontend의 브리프·대비·반응형·pre-flight를 적용하되, 후자의 마케팅 전용 히어로/이미지 규칙은 문서 탐색 도구에 적용하지 않는다. DESIGN_VARIANCE=4, MOTION_INTENSITY=2, VISUAL_DENSITY=6을 기준으로 읽기형은 밀도를 낮추고 카탈로그형은 높인다. 사진·생성 이미지는 문서 탐색에 필요하지 않다.

## 대안과 호스팅

정적 빌드는 검색 시 GitHub API 의존과 호출 한도를 없앤다. 단, 새 문서는 재빌드해야 반영된다. 브라우저 직접 GitHub 조회는 즉시 반영되지만 호출 제한과 로딩 실패를 추가한다. 기본 배포 대상은 저장소 규칙에 따라 Vercel이며 운영 단계에서 현재 공식 문서와 관련 스킬을 확인한다. 기술 스택과 원본 동기화 방법은 사용자 콘셉트 확인 후 확정한다.

## 검증

모바일 사용 빈도가 높다는 사용자 피드백을 반영한다. 모바일에서는 검색 접근성, 터치 영역, 탐색과 읽기 사이의 이동을 우선 검증한다. 현재 샘플은 세로 배치 후 문서 선택 시 본문으로 스크롤하는 방식이며, 최종 구현에서는 목록 복귀 동작도 명시적으로 제공한다.

샘플: 데스크톱·모바일 레이아웃, 키보드 포커스, 레이블, 검색 무결과/초기화, 보기 전환, 분류와 정렬 결합, 문서 선택. 운영: 빌드, 모든 문서 수집 수 비교, 상대 링크와 XSS 차단, 직접 문서 접근·새로고침, 실제 배포 URL 응답.

상태: B 그래파이트 구현·배포 완료. 원본은 공개 GitHub develop.

## 운영 구현 계약

- web/에 Vite와 네이티브 JavaScript 기반 정적 앱을 둔다. 샘플의 기존 네이티브 DOM 구성과 스타일을 발전시키며 런타임 서버와 계정은 사용하지 않는다.
- 빌드 전 공개 develop을 별도 무시 경로 .content-cache/에 가져오고 공개 커밋의 Markdown만 인덱싱한다. 사이트 소스와 로컬 미커밋 문서는 수집하지 않는다.
- public/content.json 계약: {repository, branch, commit, generatedAt, documents:[{id,path,title,category,tags,updated,markdown,text,description,sourceUrl}]}.
- 프론트매터는 YAML, Markdown은 Marked, HTML은 DOMPurify로 처리한다. Mermaid는 strict 모드로 지연 로드하고 실패 시 원본 코드를 표시한다. 폴더/태그 필터와 정렬은 두 보기에 동일 적용한다.
- 문서와 검색 상태는 URL query로 보존하고 공유하며 뒤로가기/직접 열기를 지원한다. 보기·정렬 취향은 로컬 저장소 실패 시에도 동작한다. 목록 행은 제목·태그·본문 첫 문장 기반 짧은 설명·경로·분류·수정일을 제공한다.
- 배포는 web/dist 정적 산출물만 Vercel에 업로드한다. 빌드·동기화 방법은 docs에 기록한다. 자동 Git 배포 연결은 소스 push 없이 성립하지 않으므로 완료 여부를 분리 보고한다.

최종 배포는 Vite 빌드 후 `package-vercel.mjs`가 Build Output API v3의 static/config.json 구조로 포장한다. Windows Vercel 로컬 빌드의 cmd.exe 실행 실패를 우회하며 출력 경로를 검사한 뒤 생성 산출물만 교체한다. 공개 주소는 https://jaywapp-wiki.vercel.app 이다. 날짜 정렬은 Git 수정일을 사용하고, Mermaid는 strict 모드와 SVG 정화를 함께 적용한다.

## 조사 반영

프론트매터 title을 우선하고 없으면 첫 H1, 파일명 순으로 제목을 결정한다. 태그와 category가 없는 문서는 폴더에서 분류한다. Git 실제 수정일과 프론트매터 updated는 의미가 다르므로 표시·정렬 정책을 운영 구현 시 분명히 구분한다. GFM 표와 코드 하이라이트, 안전한 Mermaid 렌더링이 필요하다. 깨진 내부 링크는 검증 보고하고 경로 추측으로 외부 URL을 만들지 않는다.

콘셉트 생성 보조 도구는 외부 카탈로그에 연결되지 않아 로컬 방향만 제공했다. 사용자의 저장소 규칙인 서로 다른 실행 가능한 샘플 3종이 우선하므로 별도 이미지 보드 대신 공통 시연 기능을 가진 세 화면을 제공한다. 시안용 시스템 글꼴은 운영 글꼴 결정으로 간주하지 않는다.
