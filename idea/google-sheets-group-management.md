# Google Sheets 기반 모임 관리 서비스

## 1. 한 줄 요약
동호회·축구팀·친목 모임 관리자가 자신의 Google Sheets를 연결해 회원, 회비, 수입·지출, 일정, 출결을 웹 UI로 관리하는 정적 웹 서비스. 별도 DB와 상시 백엔드 서버 운영을 최소화한다.

## 2. 배경 및 문제
스프레드시트는 모임 운영 자료를 직접 소유하고 편집하기 편리하지만, 모바일 입력, 회원별 납부 조회, 일정별 출결 기록과 회계 현황 파악에는 불편이 있다. 별도 데이터 서버를 운영하지 않고 기존 시트를 유지하면서 입력 경험을 개선한다.

## 3. 목표
- 관리자 전용 웹 UI로 핵심 데이터를 조회·등록·수정·삭제한다.
- 회비 납부와 기타 수입·지출을 구분해 잔액을 계산한다.
- 기존 시트 연결 및 신규 템플릿 생성을 지원한다.
- 한 계정에서 여러 모임을 전환한다.
- Google Sheets를 회계·모임 데이터의 원본으로 유지한다.

**MVP 검증 기준(제안):** 표준 템플릿 기반 CRUD 정상 동작, 기존 표 형식 시트의 열 매핑 검증, 웹/시트 금액 일치, 모바일 입력 성공, 권한 오류 및 쓰기 실패 시 데이터 손상 방지.

## 4. 대상 사용자
동호회·축구팀·친목 모임의 관리자·총무. 일반 회원은 MVP에서 로그인·조회·참석 응답을 하지 않는다. 복수 관리자는 기존 결정대로 지원하되, 각 관리자가 해당 Google Sheets에 접근 권한을 갖는 방식을 기본 검토한다.

## 5. 핵심 아이디어
정적 웹 앱에서 관리자가 Google 계정으로 로그인하고 자신에게 접근 권한이 있는 Google Spreadsheet를 연결한다. 브라우저가 Google Sheets API를 직접 호출하여 데이터를 읽고 쓴다. 별도 서비스 DB·상시 서버·정기 스케줄러는 MVP에 두지 않는다. Google OAuth 동의 화면과 API 설정은 필요하다.

## 6. 주요 사용 흐름
1. 관리자 Google 로그인 및 Sheets 접근 동의
2. 모임 선택 또는 등록
3. 기존 시트 연결·열 매핑 또는 신규 표준 템플릿 생성
4. 회원, 회비 납부, 기타 수입·지출, 일정, 출결 조회·입력·수정
5. 저장 전 필수값·참조 ID 검증 후 Sheets API 반영
6. 저장 결과 확인 및 대시보드 갱신

## 7. 핵심 기능
### 회원 관리
회원 등록·수정·비활성화, 고유 회원 ID, 이름, 가입일, 상태. 과거 회계·출결 기록과 연결된 회원은 물리 삭제보다 비활성화 권장.

### 회비 관리
회원별 회비 납부 기록의 입력·수정·조회·삭제, 납부일·금액·대상 기간 관리. 기본 회비를 설정할 수 있으나 자동 청구·복잡한 정책 이력은 MVP 제외. 미납 계산은 기준 금액·대상 기간 정책 확정 후 구체화한다.

### 회계 관리
기타 수입과 지출 등록·수정·조회·삭제, 분류·일자·메모 관리. 잔액 = 기초 잔액 + 회비 납부 합계 + 기타 수입 합계 - 지출 합계. 회비 납부를 기타 수입에 중복 기록하지 않는다.

### 일정 관리
일정 생성·수정·삭제, 제목·일시·장소·메모 관리. 반복 일정은 Later.

### 출결 관리
일정별 회원의 출석·결석·지각을 관리자가 기록·수정한다. 회원 사전 참석 응답은 MVP 제외.

### 모임 및 시트 관리
여러 모임 전환, 기존 시트 연결·열 매핑, 신규 템플릿 생성, 연결 상태 확인. 원본 시트의 기존 데이터와 열 구조를 임의로 파괴하지 않는다.

## 8. 범위
### MVP
- Google OAuth 기반 관리자 접속
- 복수 모임 및 복수 관리자(시트 공유 권한 기반)
- 기존 시트 연결·열 매핑 및 신규 템플릿
- 회원·납부·기타 수입·지출·일정·출결 CRUD
- 기본 잔액·납부·출결 대시보드
- 모바일·PC 반응형 UI
- 오류 안내 및 기본 데이터 검증

### Later
- 회원 조회 및 사전 참석 응답
- 반복 일정
- 회비 자동 청구·미납 알림
- 자동 입금 대조·영수증 OCR
- 고급 통계·보고서

### Out of Scope
- 자체 결제·은행 자동 연동
- 회원용 인증·권한 관리
- 별도 회비 DB, 상시 백엔드 서버, 자체 정기 작업
- 채팅·게시판

## 9. 결정된 사항
- 주요 대상: 동호회·축구팀·친목 모임
- 관리자 전용 서비스로 단순화; 회원 조회·직접 응답은 MVP 제외
- Google Sheets를 데이터 저장소로 사용
- 기존 시트 원본 유지·열 매핑 및 신규 템플릿 생성 지원
- 한 계정에서 여러 모임 관리
- 복수 관리자 지원
- 회원·회비·회계·일정·출결 관리
- 회비 납부와 기타 수입·지출·잔액까지 포함
- 출결 상태: 출석·결석·지각
- 반복 일정은 Later
- 별도 서버 운영 최소화가 최우선 제약
- 앞서 논의한 회원별 복잡한 회비 정책·자동 청구는 단순화된 MVP에서 제외하는 방향

## 10. 미결정 사항
- 정식 서비스명
- 부분 납부 및 미납 산정 기준
- 기본 회비의 회원별 예외 설정 여부
- 기존 시트의 지원 가능한 형식과 매핑 규칙
- 복수 관리자 동시 수정 충돌 처리
- 모임 연결 설정의 브라우저 저장·기기 간 이전 방법
- 삭제·수정 이력 및 백업 정책
- 복수 관리자 간 시트 공유 권한 정책

## 11. 데이터 및 연동
**표준 시트 탭(제안)**
| 탭 | 주요 컬럼 |
|---|---|
| Members | member_id, name, joined_at, status |
| Payments | payment_id, member_id, period, paid_at, amount |
| Transactions | transaction_id, type, category, occurred_at, amount, memo |
| Events | event_id, title, starts_at, location, memo |
| Attendance | event_id, member_id, status |
| Settings | group_name, default_fee, opening_balance |

행 번호가 아닌 고유 ID를 사용한다. 회비 납부는 Payments, 기타 수입·지출은 Transactions에 기록해 중복 합산을 방지한다. 기존 시트는 열 매핑으로 읽고, 필요한 서비스 전용 탭 추가 여부는 원본 보호를 전제로 검증한다.

## 12. 기술적 고려사항 및 위험
- 정적 웹 + Google OAuth + Google Sheets API 직접 호출을 우선 검증한다.
- OAuth 클라이언트 설정, 허용 출처, 최소 권한 범위, 토큰 수명과 재인증을 검토한다. 클라이언트 시크릿을 브라우저에 넣지 않는다.
- 복수 관리자는 원본 시트 편집 권한을 가질 수 있으므로 앱 UI만으로 직접 시트 수정을 금지할 수 없다.
- Sheets는 트랜잭션 DB가 아니므로 동시 수정·부분 쓰기 실패·중복 저장에 대한 방어가 필요하다.
- 복잡한 병합 셀·가로형 장부·수식 중심 시트는 MVP 열 매핑으로 완전히 지원되지 않을 수 있다.
- 시트 API 할당량, 네트워크 실패, 권한 철회 시 오류를 명확히 안내한다.
