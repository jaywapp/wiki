# 사내 내부 랜딩 페이지 카피 가이드

## 1. 페이지 방향

지금 만들 페이지는 사내 프로젝트의 메인 허브다.

채용 사이트가 외부 지원자에게
“이 프로젝트에 합류하고 싶다”는 마음을 만드는 페이지라면,

내부 랜딩 페이지는 사내 구성원에게
“오늘 필요한 정보와 도구를 여기서 바로 찾는다”는 확신을 주는 페이지다.

따라서 이 페이지의 핵심은 홍보가 아니라 업무 시작이다.

## 2. 화면 목적

프로젝트 구성원이 공지, 사내 솔루션, 운영 상태, 가이드, 요청 채널을 한 곳에서 확인하고 바로 이동하게 한다.

사용자가 이 화면에서 끝내야 할 일:
- 오늘 확인해야 할 공지를 본다.
- 자주 쓰는 사내 도구로 이동한다.
- 빌드, 점검, 장애 상태를 확인한다.
- 신규 구성원은 온보딩 자료를 찾는다.
- 문제가 생기면 요청 채널로 이동한다.

## 3. 대상 사용자

프로젝트 내부 구성원 전체.

대상:
- 개발
- 기획
- 아트
- 사운드
- QA
- PM
- 운영/지원 조직
- 신규 입사자
- 협업 부서 구성원

사용자 상황:
- 이미 바쁜 상태에서 필요한 링크를 찾고 있다.
- Slack, 문서, 사내 도구, 공지 채널이 흩어져 있어 피로도가 있다.
- 신규 구성원은 무엇부터 봐야 할지 모른다.
- 기존 구성원도 자주 쓰는 도구의 위치를 매번 찾는다.

## 4. 사용자 문제

현재 문제:
- 사내 솔루션 접근 경로가 흩어져 있다.
- 공지와 변경사항을 놓치기 쉽다.
- 신규 구성원이 필요한 자료를 찾기 어렵다.
- 장애나 점검 상태를 늦게 알게 된다.
- 권한 요청, 오류 제보, 개선 요청의入口가 명확하지 않다.

사용자가 느끼는 불편:
- “어디서 봐야 하지?”
- “이 도구 링크가 뭐였지?”
- “공지 올라온 게 있었나?”
- “이 장애가 나만 겪는 건가?”
- “권한은 누구한테 요청하지?”

## 5. 사용자가 얻을 결과

이 페이지를 통해 사용자는 다음 결과를 얻는다.

- 프로젝트의 오늘 상태를 빠르게 파악한다.
- 필요한 도구로 바로 이동한다.
- 중요한 공지를 놓치지 않는다.
- 신규 구성원은 시작 순서를 알 수 있다.
- 문제가 생겼을 때 요청 경로를 고민하지 않는다.
- 흩어진 정보를 찾는 시간을 줄인다.

## 6. 핵심 메시지

메인 카피 추천:

프로젝트의 하루를 여기서 시작하세요

보조 카피:

공지, 도구, 가이드, 요청 채널을 한 곳에 모았습니다.
필요한 정보를 찾고 바로 업무를 시작하세요.

조금 더 프로젝트 톤을 살린 버전:

우리가 만드는 세계의 오늘을 확인하세요

공지, 도구, 운영 상태, 가이드를 한 곳에서 확인하고
오늘 필요한 업무로 바로 이동하세요.

더 실무적인 버전:

공지부터 사내 도구까지, 한 곳에서 시작하세요

프로젝트에 필요한 링크와 최신 알림을 모았습니다.
찾는 시간을 줄이고 바로 업무를 시작하세요.

## 8. 섹션별 카피

1) Hero

제목:
프로젝트의 하루를 여기서 시작하세요

설명:
공지, 도구, 가이드, 요청 채널을 한 곳에 모았습니다.
필요한 정보를 찾고 바로 업무를 시작하세요.

CTA:

- 오늘의 공지 보기

보조 안내:
이 페이지는 프로젝트 구성원을 위한 내부 업무 허브입니다.

2) 오늘 확인할 내용

제목:
오늘 확인해야 할 내용입니다

설명:
점검, 장애, 배포, 규칙 변경처럼 업무에 영향을 주는 소식을 먼저 보여줍니다.

공지 카드 문구:
- 빌드 서버 점검 예정
  오늘 19:00부터 일부 빌드 요청이 지연될 수 있습니다.
  CTA: 점검 내용 확인하기

- 제출 규칙 변경
  신규 제출 전 필수 검증 항목이 추가되었습니다.
  CTA: 변경된 규칙 보기

- 데이터 도구 업데이트
  테이블 비교 화면과 저장 안내 문구가 변경되었습니다.
  CTA: 업데이트 내용 보기

빈 상태:
현재 확인해야 할 중요 공지가 없습니다.

3) 자주 쓰는 솔루션

제목:
필요한 도구로 바로 이동하세요

설명:
반복해서 찾는 사내 솔루션을 업무 목적별로 모았습니다.

카드 예시:

- 변경사항 제출
  CL 확인, 제출 설명 작성, 리뷰 요청을 진행합니다.
  CTA: 제출 도구 열기

- 빌드 상태 확인
  최신 빌드 결과와 실패 원인을 확인합니다.
  CTA: 빌드 상태 보기

- 데이터 편집
  프로젝트 테이블 데이터를 확인하고 수정합니다.
  CTA: 데이터 도구 열기

- 설치와 환경 설정
  필수 프로그램과 작업 환경을 순서대로 설정합니다.
  CTA: 설치 가이드 시작하기

- 크래시 확인
  크래시 분석 결과와 처리 상태를 확인합니다.
  CTA: 크래시 현황 보기

4) 프로젝트 운영 상태

제목:

설명:
빌드, 서버, 도구, 데이터 처리 상태를 한눈에 확인합니다.

상태 문구:
- 정상
  모든 주요 시스템이 정상 동작 중입니다.

- 주의
  일부 작업이 평소보다 오래 걸리고 있습니다.

- 장애
  일부 도구에 접속할 수 없습니다. 조치 내용을 확인하세요.

CTA:
- 전체 상태 보기
- 장애 제보하기

5) 신규 구성원 시작하기

제목:
처음 합류했다면 여기서 시작하세요

설명:
계정, 권한, 설치, 기본 도구 사용법을 순서대로 확인할 수 있습니다.

단계:
1. 계정과 권한 확인
2. 필수 프로그램 설치
3. 프로젝트 작업 공간 설정
4. P4, 빌드, 데이터 도구 사용법 확인
5. 문의 채널 입장

CTA:
- 온보딩 가이드 시작하기
- 필수 설치 목록 보기

6) 요청하기

제목:

설명:

요청 카드:
- 권한 요청
  접근이 필요한 도구나 문서를 신청합니다.
  CTA: 권한 요청하기

- 오류 제보
  도구 오류, 접속 문제, 실패 상황을 전달합니다.
  CTA: 오류 제보하기

- 개선 의견
  반복되는 불편이나 개선 아이디어를 남깁니다.
  CTA: 개선 의견 보내기

7) 프로젝트 가이드

제목:

## 10. 상태별 문구

빈 상태:
- 현재 확인해야 할 중요 공지가 없습니다.
- 등록된 즐겨찾기 도구가 없습니다. 자주 쓰는 도구를 추가해 보세요.
- 표시할 장애 내역이 없습니다.
- 아직 등록된 온보딩 자료가 없습니다.

로딩:
- 프로젝트 정보를 불러오는 중입니다.
- 최신 공지와 도구 상태를 확인하고 있습니다.
- 요청 채널 정보를 불러오는 중입니다.

성공:
- 요청이 접수되었습니다. 담당자가 확인 후 안내합니다.
- 즐겨찾기에 추가했습니다. 이제 메인에서 바로 열 수 있습니다.
- 공지를 읽음 처리했습니다.
- 설정이 저장되었습니다.

실패:
- 공지를 불러오지 못했습니다. 네트워크 상태를 확인한 뒤 다시 시도하세요.
- 도구 상태를 확인하지 못했습니다. 잠시 후 다시 열어보세요.
- 요청을 접수하지 못했습니다. 입력 내용을 확인하고 다시 보내주세요.
- 권한이 없어 이 페이지를 열 수 없습니다. 접근이 필요하면 권한을 요청하세요.

경고:
- 이 작업은 선택한 도구의 권한 요청을 생성합니다.
- 일부 시스템이 점검 중입니다. 진행 중인 작업은 저장 후 다시 시도하세요.
- 오래된 링크일 수 있습니다. 최신 경로를 확인하세요.

## 11. 디자인 방향 메모

전체 분위기:
- 내부 업무용
- 차분함
- 신뢰감
- 프로젝트 세계관은 약하게 반영
- 과한 홍보 느낌은 피함

정보 밀도:
- 첫 화면은 복잡하지 않게 구성
- 공지와 도구는 빠르게 스캔 가능해야 함
- 상세 내용은 클릭 후 확인하도록 분리

강조해야 할 정보:
- 오늘 확인해야 할 공지
- 자주 쓰는 도구
- 장애와 점검 상태
- 신규 구성원이 시작할入口
- 요청 채널

피해야 할 요소:
- 추상적인 슬로건 남발
- 장식용 카드 과다 사용
- 도구 이름만 나열하는 구성
- “확인”, “바로가기” 같은 모호한 버튼
- 공지와 홍보성 콘텐츠가 섞여 우선순위가 흐려지는 구성

카드 사용 기준:
- 도구 카드는 “도구명 + 사용 목적 + CTA” 구조로 작성
- 공지 카드는 “제목 + 영향 범위 + 필요한 행동” 구조로 작성
- 상태 카드는 “정상/주의/장애 + 영향 + 다음 행동” 구조로 작성

모바일 우선순위:
1. 중요 공지
2. 자주 쓰는 도구
3. 장애/점검 상태
4. 요청하기
5. 온보딩 가이드

## 12. 구현 AI에게 전달할 요약

사내 내부 랜딩 페이지를 만든다.
이 페이지는 프로젝트의 메인 도메인 역할을 하며, 구성원이 공지, 사내 솔루션, 운영 상태, 온보딩 자료, 요청 채널에 빠르게 접근하도록 돕는다.

핵심 메시지:
프로젝트의 하루를 여기서 시작하세요

보조 메시지:
공지, 도구, 가이드, 요청 채널을 한 곳에 모았습니다.
필요한 정보를 찾고 바로 업무를 시작하세요.

메인 CTA:
자주 쓰는 도구 열기

보조 CTA:
오늘의 공지 보기

섹션 순서:
1. Hero
2. 오늘 확인할 내용
3. 자주 쓰는 솔루션
4. 프로젝트 운영 상태
5. 신규 구성원 시작하기
6. 요청하기
7. 프로젝트 가이드

UX 주의사항:
- 사용자가 해야 할 행동이 먼저 보여야 한다.
- 도구 이름보다 사용 목적을 먼저 보여야 한다.
- 장애와 점검 상태는 일반 공지보다 더 강하게 보여야 한다.
- 신규 구성원이 헤매지 않도록 온보딩入口를 첫 화면 가까이에 둔다.
- 버튼 문구는 사용자의 실제 행동으로 작성한다.
- 실패 문구에는 원인과 다음 행동을 반드시 포함한다.
