# 사내 내부 랜딩 페이지 디자인 브리프

## 1. 프로젝트 개요

이번에 제작할 페이지는 프로젝트 구성원을 위한 사내 내부 랜딩 페이지입니다.

외부 사용자를 설득하는 홍보 페이지가 아니라,
사내 구성원이 매일 필요한 공지, 내부 솔루션, 운영 상태, 가이드, 요청 채널에 빠르게 접근하기 위한 업무 허브입니다.

이 페이지는 사내 메인 도메인으로 사용될 예정이며,
프로젝트 구성원이 업무를 시작할 때 가장 먼저 방문하는入口 역할을 해야 합니다.

## 2. 디자인 목표

사용자가 이 페이지에 들어왔을 때 5초 안에 다음을 이해해야 합니다.

- 여기는 프로젝트 내부 업무 허브다.
- 오늘 확인해야 할 공지가 있다면 바로 볼 수 있다.
- 자주 쓰는 사내 도구로 바로 이동할 수 있다.
- 빌드, 점검, 장애 같은 운영 상태를 확인할 수 있다.
- 신규 구성원은 온보딩 자료를 찾을 수 있다.
- 문제가 생기면 어디에 요청해야 하는지 알 수 있다.

핵심 목표는 예쁜 화면이 아니라,
사용자가 필요한 정보와 다음 행동을 빠르게 찾게 만드는 것입니다.

## 3. 참고 톤

기존 프로젝트 채용 사이트의 느낌은 참고하되,
내부 페이지에서는 감성보다 실용성이 더 중요합니다.

참고할 점:
- 프로젝트에 속해 있다는 느낌
- 차분하고 신뢰감 있는 분위기
- 하나의 세계관 안에서 일한다는 인상
- 구성원을 환영하는 톤

그대로 가져오면 안 되는 점:
- 외부 홍보용 슬로건 중심 구성
- 감성 문구가 많은 구조
- 긴 스토리텔링 흐름
- 지원 전환 중심의 페이지 흐름

내부 랜딩 페이지에서는
“합류하고 싶다”가 아니라
“오늘 필요한 일을 여기서 시작한다”가 핵심입니다.

## 4. 대상 사용자

주 사용자:
- 개발자
- 기획자
- 아티스트
- 사운드 담당자
- QA
- PM
- 운영/지원 조직
- 신규 입사자
- 협업 부서 구성원

사용자 상황:
- 이미 바쁜 업무 중 필요한 링크를 찾고 있음
- 공지, 문서, Slack, 사내 도구가 흩어져 있어 피로도가 있음
- 신규 구성원은 무엇부터 봐야 할지 모름
- 기존 구성원도 도구 위치나 최신 공지를 반복해서 찾음
- 장애나 점검 정보를 빠르게 확인해야 함

## 5. 핵심 사용자 문제

사용자가 겪는 문제는 다음과 같습니다.

- 사내 솔루션 접근 경로가 흩어져 있다.
- 중요한 공지와 변경사항을 놓치기 쉽다.
- 신규 구성원이 온보딩 자료를 찾기 어렵다.
- 빌드, 점검, 장애 상태를 한눈에 보기 어렵다.
- 권한 요청, 오류 제보, 개선 요청入口가 명확하지 않다.
- 도구 이름만으로는 어떤 업무에 쓰는지 알기 어렵다.

디자인은 이 문제를 줄이는 방향으로 구성되어야 합니다.

## 6. 핵심 메시지

메인 메시지:
프로젝트의 하루를 여기서 시작하세요

보조 메시지:
공지, 도구, 가이드, 요청 채널을 한 곳에 모았습니다.
필요한 정보를 찾고 바로 업무를 시작하세요.

조금 더 프로젝트 톤을 살린 대안:
우리가 만드는 세계의 오늘을 확인하세요

실무적인 대안:
공지부터 사내 도구까지, 한 곳에서 시작하세요

디자인에서는 메인 메시지를 크게 보여주되,
문장이 과하게 감성적으로 보이지 않도록 해야 합니다.

   - 점검
   - 장애
   - 배포
   - 규칙 변경

3. 자주 쓰는 솔루션

   - 업무 목적별 카드 구성

4. 프로젝트 운영 상태
   - 빌드 상태
   - 주요 시스템 상태
   - 점검/장애 여부

5. 신규 구성원 시작하기
   - 계정
   - 권한
   - 설치
   - 작업 환경
   - 기본 가이드

6. 요청하기
   - 권한 요청
   - 오류 제보
   - 개선 의견
   - 도구 문의

7. 프로젝트 가이드
   - 일하는 방식
   - 제출 규칙
   - 협업 규칙
   - 문서 모음

## 8. Hero 디자인 방향

Hero는 과하게 큰 비주얼보다
업무 시작점이라는 역할을 명확히 보여줘야 합니다.

포함 요소:
- 메인 카피
- 보조 설명
- 메인 CTA
- 보조 CTA
- 현재 날짜 또는 오늘의 요약
- 중요 알림이 있을 경우 상단 배지

Hero 카피:
프로젝트의 하루를 여기서 시작하세요

설명:
공지, 도구, 가이드, 요청 채널을 한 곳에 모았습니다.
필요한 정보를 찾고 바로 업무를 시작하세요.

CTA:
- 자주 쓰는 도구 열기
- 오늘의 공지 보기

디자인 메모:
- 첫 화면에서 가장 크게 보이는 것은 메인 카피와 오늘의 주요 행동이어야 함
- 배경은 과하게 장식하지 말 것
- 프로젝트 아이덴티티는 은은하게 반영
- 내부 업무 도구 느낌을 유지

## 9. 오늘 확인할 내용 섹션

이 섹션은 페이지 상단 가까이에 있어야 합니다.
사용자가 놓치면 안 되는 정보를 가장 먼저 확인하게 해야 합니다.

섹션 제목:
오늘 확인해야 할 내용입니다

설명:
점검, 장애, 배포, 규칙 변경처럼 업무에 영향을 주는 소식을 먼저 보여줍니다.

카드 구성:
- 공지 제목
- 유형 배지
- 영향 범위
- 날짜/시간
- 필요한 행동
- CTA

예시 CTA:
- 점검 내용 확인하기
- 변경된 규칙 보기
- 업데이트 내용 보기

디자인 메모:
- 공지와 홍보성 콘텐츠를 섞지 말 것
- 장애와 점검은 일반 공지보다 더 강하게 표시
- 카드가 많아질 경우 중요도 순으로 정렬
- 읽음/안 읽음 상태를 구분할 수 있으면 좋음

## 10. 자주 쓰는 솔루션 섹션

이 페이지의 핵심 섹션입니다.
도구 이름만 나열하지 말고,
사용자가 하려는 일 중심으로 보여줘야 합니다.

섹션 제목:
필요한 도구로 바로 이동하세요

설명:
반복해서 찾는 사내 솔루션을 업무 목적별로 모았습니다.

카드 구조:
- 사용 목적
- 짧은 설명
- 도구명 또는 관련 시스템
- CTA
- 즐겨찾기 가능 여부

카드 예시:
1. 변경사항 제출
   설명: CL 확인, 제출 설명 작성, 리뷰 요청을 진행합니다.
   CTA: 제출 도구 열기

2. 빌드 상태 확인
   설명: 최신 빌드 결과와 실패 원인을 확인합니다.
   CTA: 빌드 상태 보기

3. 데이터 편집
   설명: 프로젝트 테이블 데이터를 확인하고 수정합니다.
   CTA: 데이터 도구 열기

4. 설치와 환경 설정
   설명: 필수 프로그램과 작업 환경을 순서대로 설정합니다.
   CTA: 설치 가이드 시작하기

5. 크래시 확인
   설명: 크래시 분석 결과와 처리 상태를 확인합니다.
   CTA: 크래시 현황 보기

디자인 메모:
- 카드 수가 많아질 수 있으므로 검색 또는 카테고리 필터를 고려
- 즐겨찾기 도구는 상단에 고정할 수 있으면 좋음
- 아이콘은 장식이 아니라 도구 목적을 빠르게 구분하는 용도로 사용
- 카드 높이는 일정하게 맞추되 설명은 2줄 이내 권장

## 11. 프로젝트 운영 상태 섹션

사용자는 현재 시스템이 정상인지 빠르게 알아야 합니다.

섹션 제목:
지금 프로젝트 상태를 확인하세요

설명:
빌드, 서버, 도구, 데이터 처리 상태를 한눈에 확인합니다.

상태 구분:
- 정상
- 주의
- 장애
- 점검 중

상태 문구:
- 정상: 모든 주요 시스템이 정상 동작 중입니다.
- 주의: 일부 작업이 평소보다 오래 걸리고 있습니다.
- 장애: 일부 도구에 접속할 수 없습니다. 조치 내용을 확인하세요.
- 점검 중: 현재 점검 중입니다. 점검이 끝나면 다시 사용할 수 있습니다.

CTA:
- 전체 상태 보기
- 장애 제보하기

디자인 메모:
- 상태는 색상만으로 구분하지 말고 텍스트와 아이콘을 함께 사용
- 장애가 있을 경우 상단 공지 영역과 연결
- 상세 로그나 긴 설명은 접거나 별도 페이지로 이동
- 사용자가 지금 영향을 받는지 알 수 있어야 함

## 12. 신규 구성원 시작하기 섹션

신규 구성원이 헤매지 않도록 중간 이상 위치에 배치합니다.

섹션 제목:
처음 합류했다면 여기서 시작하세요

설명:
계정, 권한, 설치, 기본 도구 사용법을 순서대로 확인할 수 있습니다.

단계:
1. 계정과 권한 확인
2. 필수 프로그램 설치
3. 프로젝트 작업 공간 설정
4. P4, 빌드, 데이터 도구 사용법 확인
5. 문의 채널 입장

CTA:
- 온보딩 가이드 시작하기
- 필수 설치 목록 보기

디자인 메모:
- 단계형 UI가 적합
- 현재 단계와 완료 여부를 표시할 수 있으면 좋음
- 신규 구성원만 보는 정보처럼 숨기지 말고, 기존 구성원도 다시 찾을 수 있게 구성
- 너무 많은 설명은 피하고 가이드 페이지로 연결

## 13. 요청하기 섹션

문제가 생겼을 때 누구에게 물어볼지 고민하지 않게 해야 합니다.

섹션 제목:
막히는 일이 있으면 바로 요청하세요

설명:
권한, 오류, 개선 요청을 목적에 맞는 채널로 전달합니다.

요청 카드:
1. 권한 요청
   설명: 접근이 필요한 도구나 문서를 신청합니다.
   CTA: 권한 요청하기

2. 오류 제보
   설명: 도구 오류, 접속 문제, 실패 상황을 전달합니다.
   CTA: 오류 제보하기

3. 개선 의견
   설명: 반복되는 불편이나 개선 아이디어를 남깁니다.
   CTA: 개선 의견 보내기

디자인 메모:
- 문의 채널을 너무 많이 나열하지 말 것
- 사용자가 요청 유형을 고르면 다음 경로가 명확해야 함
- 오류 제보는 필요한 정보 예시를 함께 안내하면 좋음
- 긴 양식보다 빠른入口가 중요

## 14. 프로젝트 가이드 섹션

이 섹션은 하단 보조 영역으로 배치합니다.
일하는 방식과 규칙을 찾을 수 있는 문서 모음 역할입니다.

섹션 제목:
우리가 함께 일하는 방식입니다

설명:
제출 규칙, 협업 방식, 문서 작성 기준, 도구 사용법을 모았습니다.

CTA:
- 프로젝트 가이드 보기
- 제출 규칙 확인하기

디자인 메모:
- 감성적인 톤은 이 섹션에서 약하게 사용 가능
- 채용 사이트의 프로젝트 톤을 내부용으로 이어받는 영역
- 상단 업무 영역보다 시각적 우선순위는 낮게 설정

## 15. 전체 비주얼 방향

분위기:
- 업무용
- 차분함
- 신뢰감
- 명확함
- 과장 없음
- 프로젝트 아이덴티티는 은은하게 반영

피해야 할 분위기:
- 외부 홍보 페이지처럼 과하게 감성적인 구성
- 화려한 그라데이션 중심 디자인
- 장식용 카드가 많은 화면
- 슬로건만 크고 실제 행동이 약한 화면
- 내부 용어만 나열된 화면

색상 사용 방향:
- 기본 배경은 안정적이고 읽기 쉬운 톤
- 중요 공지, 장애, 점검 상태는 명확히 구분
- CTA는 한 화면에서 가장 중요한 행동만 강하게 강조
- 상태 색상은 텍스트 라벨과 함께 사용

정보 밀도:
- 내부 도구이므로 너무 비우지 말 것
- 하지만 첫 화면은 복잡하지 않아야 함
- 주요 정보는 카드로 빠르게 스캔 가능하게 구성
- 상세 설명은 접거나 별도 페이지로 이동

- 확인
- 다음
- 바로가기
- 자세히 보기
- 처리하기
- 진행
- 완료

## 17. 상태별 화면 문구

빈 상태:
- 현재 확인해야 할 중요 공지가 없습니다.
- 등록된 즐겨찾기 도구가 없습니다. 자주 쓰는 도구를 추가해 보세요.
- 표시할 장애 내역이 없습니다.
- 아직 등록된 온보딩 자료가 없습니다.

로딩:
- 프로젝트 정보를 불러오는 중입니다.
- 최신 공지와 도구 상태를 확인하고 있습니다.
- 요청 채널 정보를 불러오는 중입니다.

성공:
- 요청이 접수되었습니다. 담당자가 확인 후 안내합니다.
- 즐겨찾기에 추가했습니다. 이제 메인에서 바로 열 수 있습니다.
- 공지를 읽음 처리했습니다.
- 설정이 저장되었습니다.

실패:
- 공지를 불러오지 못했습니다. 네트워크 상태를 확인한 뒤 다시 시도하세요.
- 도구 상태를 확인하지 못했습니다. 잠시 후 다시 열어보세요.
- 요청을 접수하지 못했습니다. 입력 내용을 확인하고 다시 보내주세요.
- 권한이 없어 이 페이지를 열 수 없습니다. 접근이 필요하면 권한을 요청하세요.

경고:
- 이 작업은 선택한 도구의 권한 요청을 생성합니다.
- 일부 시스템이 점검 중입니다. 진행 중인 작업은 저장 후 다시 시도하세요.
- 오래된 링크일 수 있습니다. 최신 경로를 확인하세요.

## 18. 반응형 우선순위

모바일 또는 작은 화면에서는 다음 순서로 노출합니다.

1. 중요 공지
2. 자주 쓰는 도구
3. 장애/점검 상태
4. 요청하기
5. 온보딩 가이드
6. 프로젝트 가이드

모바일 디자인 메모:
- Hero 영역을 너무 크게 만들지 말 것
- 공지와 장애 상태가 먼저 보여야 함
- 도구 카드는 1열 카드형이 적합
- CTA는 카드 하단에 명확하게 배치
- 긴 설명보다 제목과 행동을 우선
