# AI Knowledge Base Orchestration

이 문서는 `ai/` 하위에 추가되는 문서를 일관된 기준으로 분류하기 위한 운영 규칙이다.

## 기본 구조

```text
ai/
├── README.md
├── Orchestration.md
├── news/
├── tips/
├── harness/
├── tools/
├── skills/
├── research/
└── etc/
```

## 분류 규칙

### `news/`
AI·에이전트 생태계의 새로운 소식과 변화.

- 신규 모델 및 서비스 출시
- 주요 버전 업데이트
- 제품·플랫폼 정책 변화
- 업계 주요 발표
- 시점 자체가 중요한 정보

시간이 지나면 정보 가치가 크게 달라지는 자료를 우선 배치한다.

### `tips/`
실제 개발·업무 환경에서 바로 적용할 수 있는 노하우.

- 토큰 절약 및 비용 최적화
- Claude Code / Codex 등의 설정 방법
- 프롬프트 및 컨텍스트 운영법
- 개발 환경 구성
- 문제 해결 및 운영 팁
- 특정 도구의 실전 사용 패턴

핵심 판단 기준은 **"이 문서를 보고 바로 적용할 수 있는가?"** 이다.

### `harness/`
하나 이상의 모델·에이전트·도구를 조합해 작업을 수행하는 실행 구조와 워크플로우.

- Claude + Codex 조합
- Opus / Fable + DeepSeek 조합
- 멀티 에이전트 구조
- Orchestrator / Worker / Reviewer 패턴
- 모델 라우팅
- 에이전트 실행기 및 런처
- 컨텍스트 전달 및 세션 관리 구조

단일 도구 자체보다 **여러 구성 요소를 어떻게 연결해서 사용하는지**가 핵심이면 이곳에 둔다.

### `tools/`
AI 및 Agent Experience를 확장하는 독립적인 도구·프로젝트·프레임워크.

- MCP 서버
- Agent Framework
- CLI / Desktop 도구
- 코드베이스 분석 도구
- 메모리·검색·브라우저 등 에이전트 보조 도구
- GitHub에서 발견한 AI 관련 프로젝트 분석

특정 프로젝트나 제품 자체를 설명하는 문서는 기본적으로 `tools/`를 우선 고려한다.

### `skills/`
에이전트가 특정 작업을 더 잘 수행하도록 만드는 Skill 및 재사용 가능한 작업 지침.

- Claude Code Skills
- Agent Skills
- UI/UX Skill
- Browser Skill
- MCP Builder Skill
- 개발·디버깅·검증 Skill
- 여러 Skill의 비교

Skill 자체 또는 Skill을 조합하는 방법이 핵심인 경우 이곳에 둔다.

### `research/`
단순 소개보다 비교·검증·분석이 중심인 자료.

- 모델 비교
- 도구 비교
- Enterprise AI 분석
- 성능·비용 분석
- 실사용 사례 조사
- 기술 구조 심층 분석
- 벤치마크 및 실험 결과

문서의 핵심 질문이 **"무엇인가?"보다 "어떤 것이 더 적합한가 / 실제로 어떤가?"** 에 가까우면 `research/`로 분류한다.

### `etc/`
위 카테고리에 명확하게 들어가지 않는 AI 관련 자료.

`etc/`는 임시 보관소가 아니라 예외 카테고리다. 비슷한 자료가 반복적으로 쌓이면 새로운 정식 카테고리를 만드는 것을 우선 검토한다.

## 분류 우선순위

하나의 문서가 여러 성격을 가지는 경우 문서의 **주된 목적**을 기준으로 하나의 카테고리만 선택한다.

판단 순서는 다음과 같다.

1. 시점이 핵심인가? → `news`
2. Skill 자체가 핵심인가? → `skills`
3. 여러 모델/에이전트/도구의 연결 구조가 핵심인가? → `harness`
4. 특정 도구·프로젝트 자체가 핵심인가? → `tools`
5. 바로 적용할 운영 노하우가 핵심인가? → `tips`
6. 비교·실험·심층 분석이 핵심인가? → `research`
7. 어디에도 명확히 속하지 않는가? → `etc`

## 문서 추가 원칙

- 기본 파일명은 영문 kebab-case를 사용한다.
- 프로젝트 고유명사는 공식 표기를 우선한다.
- 같은 주제의 문서를 불필요하게 여러 카테고리에 복제하지 않는다.
- 기존 문서와 주제가 겹치면 새 문서를 만들기 전에 통합 가능성을 검토한다.
- GitHub 프로젝트 분석 문서는 원본 저장소 링크를 포함한다.
- 조사 시점이 중요한 문서는 조사 날짜 또는 기준 버전을 명시한다.
- 분류가 애매하면 `etc`에 바로 넣기보다 문서의 목적을 먼저 판단한다.

## 카테고리 확장 규칙

새 카테고리는 다음 조건을 만족할 때 추가한다.

1. 기존 카테고리로 설명하기 어려운 동일 성격의 문서가 반복해서 생성된다.
2. 최소 3개 이상의 문서가 독립적인 주제군을 형성한다.
3. 향후에도 지속적으로 자료가 추가될 가능성이 높다.

새 카테고리를 추가하면 이 문서와 `ai/README.md`의 구조 및 설명도 함께 갱신한다.
