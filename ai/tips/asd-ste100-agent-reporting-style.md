# ASD-STE100에서 착안한 AI Agent 결과 보고 방식

## 핵심 요약
2026-10-24 제공된 Threads 캡처는 AI 응답을 더 쉽게 이해하도록 만드는 네 가지 출력 형식(ASD-STE100 항공정비 언어, 다이어그램, HTML, 영상)을 소개한다. 게시물 작성자는 특정 에이전트에 항공정비식 보고 규칙을 적용한 뒤 전체 에이전트로 확장했다고 주장한다. 이는 **게시물의 경험담**이며 객관적인 효과 측정 결과는 아니다.

## 개념과 사실 구분
- ASD-STE100(Simplified Technical English)은 항공우주 기술 문서의 명료성과 일관성을 위한 통제 영어 표준이다.
- 캡처에 등장한 간결한 역할별 보고가 ASD-STE100 규격을 엄격하게 준수한다는 증거는 없다. 실무에서는 'ASD-STE100-inspired'로 표현하는 것이 정확하다.
- 단순히 짧은 문장을 쓰는 것과 통제 어휘·문장 규칙을 충족하는 것은 다르다.

## 게시물의 네 가지 방식
| 출력 형식 | 목적 | 적합한 용도 |
| --- | --- | --- |
| 항공정비식 언어 | 모호함 감소, 행동 중심 보고 | 에이전트 상태 보고 |
| 다이어그램 | 구성 요소와 관계 표현 | 워크플로우, 아키텍처 |
| HTML | 정보의 계층화 | 복잡한 분석, 대시보드 |
| 영상 | 절차와 변화 시연 | 교육 및 데모 |

## 권장 에이전트 보고 구조
```text
상태: 완료 / 부분 완료 / 차단

에이전트가 한 일
- [검증된 작업만 간단히 기록]

내가 확인할 일
- [검토 또는 승인 필요 항목]

사용자가 할 일
- [사용자에게 실제로 필요한 행동]

문제 및 위험
- [실패, 미확인 사항, 영향]

다음 단계
- [실행 주체와 후속 행동]
```

## 재사용 프롬프트 예시
```text
작업 결과를 ASD-STE100에서 착안한 간결한 기술 보고 방식으로 작성하라.
- 한 문장에 하나의 사실 또는 행동만 담는다.
- 짧고 구체적인 동사를 사용한다.
- 완료, 실패, 미검증을 구분한다.
- '에이전트가 한 일 / 내가 확인할 일 / 사용자가 할 일'을 구분한다.
- 불필요한 수식어를 제거하되 오류, 제약, 근거, 보안 위험은 생략하지 않는다.
- 해당 없는 섹션은 생략한다.
- ASD-STE100 공식 준수를 주장하지 않는다.
```

## 적용 및 검증 제안
Claude Code, Codex 및 다중 에이전트 워크플로우의 최종 결과 보고에 적용할 수 있다. 기존 Concise 출력과 비교할 때 보고서 길이뿐 아니라 **누락된 위험 정보, 작업 주체 식별 정확도, 사용자 후속 행동의 명확성**을 평가한다. Enterprise 환경에서는 비밀정보를 로그에 포함하지 않도록 별도 출력 정책을 유지한다.

## 한계
원본 Threads URL, 게시물 작성자와 정확한 작성일, 영상의 전체 맥락은 캡처만으로 검증되지 않았다. 이미지 안의 작은 보고서 예시는 전체 문구를 정확히 판독하지 않고 구조만 참고했다. 공식 ASD-STE100 원문과의 규격 대조는 수행하지 않았다.
